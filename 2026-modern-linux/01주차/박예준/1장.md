# 1장. 리눅스 소개

- 모던 환경에서의 리눅스 역할
  - 모바일 디바이스 - AndroidOS는 리눅스의 변형 https://www.androidauthority.com/android-linux-784964/
    - Android = Linux kernel 기반의 특수 목적 모바일 OS (linux 배포판은 아니지만 커널을 기반함)
      | 관점 | 설명 |
      | ------------------- | --------------------------------------------------------------------------------------- |
      | Linux 커널 기준 | Android는 Linux 맞음. 모든 Android 기기는 Linux kernel 기반 |
      | Linux 배포판 기준 | 애매함. Ubuntu/Fedora 같은 일반 Linux distro와 구조·철학·호환성이 많이 다름 |
      | GNU/Linux 기준 | Android는 거의 아님. GNU userland 대신 Android 전용 라이브러리/Bionic 등을 사용 |
      | 앱 호환성 기준 | 일반 Linux 앱을 바로 실행하기 어렵고, Android 앱도 Android 런타임이 필요 |
      | 오픈소스 기준 | AOSP는 오픈소스지만, 실제 상용 Android에는 Google/제조사 proprietary 코드가 많이 포함됨 |
      | root/customize 기준 | 일반 Linux보다 OS 내부 접근과 수정이 훨씬 제한적 |
  - 클라우드 컴퓨팅 - 오픈소스 소프트웨어 관점에서의 대규모 아웃소싱, 성공적인 ARM 기반의 AWS Graviton
    - https://docs.aws.amazon.com/prescriptive-guidance/latest/optimize-costs-microsoft-workloads/net-graviton.html
  - (스마트) 사물인터넷 - 전력 소비, 실시간 기능 요구사항에서 까다로움
    - https://developer.toradex.com/software/real-time/real-time-linux/ - **Linux를 더 낮은 지연시간/예측 가능한 동작에 맞게 튜닝해서 쓰는 방식**
      - Real-Time Linux = Linux를 실시간성에 가깝게 만들 수는 있지만, 최종 latency 보장은 직접 튜닝/측정/검증해야 한다. (`cyclictest`)
      - 실시간 처리 방식 - Linux 단독 튜닝, PREEMPT_RT 패치, 하이퍼바이저/코커널, 별도 RTOS와 멀티코어 분리 실행 같은 선택지가 있음
        - `PREEMPT_RT` - Linux 커널을 더 preemptive하게 만들어 지연시간을 줄이는 대표 방식
      - 한계 - Linux는 범용 OS라 hard real-time 보장은 약함 (사용 환경별 검증 필요)
  - 프로세서 아키텍처의 다양성 - ARM, RISC-V, Go/Rust 등 다중 아키텍처 프로그래밍 언어
- 리눅스의 역사
  - 1990s
    - LOC 수, 도입률 측면에서 화제가 됨
    - 대부분의 유닉스/GNU 소프트웨어를 실행하게 만든다는 목표로 시작
    - 최초 상용 제품 ‘Red Hat’
  - 2000s
    - 배포판 전쟁의 정점 - _“커널 하나에서 시작해 수많은 배포판 생태계로 확장되다”_
    - 오픈소스와 배포판 생태계를 통해 서버, 클라우드, 모바일 기반 기술까지 흔든 거대한 운영체제 계열로 성장했다
    - 분화와 파생 형태의 발전 - Debian, Red Hat/Fedora, SUSE, Arch, Gentoo 계열 → Ubuntu, Mint 등 파생 배포판
      - 각 배포판은 패키지 관리, 업데이트 방식, 데스크탑 환경, 기본 앱, 하드웨어 요구사항 등을 다르게 설계
  - 2010s~
    - 요즘 대부분의 사용 시스템은 RedHat, Debian 기반
    - 컨테이너 급부상의 계기가 되었다고 볼 수 있음
- 운영체제의 필요성
  - OS는 하드웨어를 추상화하고 자원을 관리하며, 프로그램은 system call을 통해 OS가 제공하는 기능을 사용한다
  - system call은 커널이 제공하는 낮은 수준의 인터페이스로, 일반 프로그램은 보통 라이브러리 API를 통해 간접적으로 system call을 사용한다
  - 설치공간이 작은 임베디드 시스템에서는 OS 없이 베어메탈 환경에서 구축되기도 한다
- 리눅스 배포판
  - _커널 = 시스템 콜 인터페이스 + 자원 관리 기능 + 파일/네트워크/메모리/프로세스 관리 + 디바이스 드라이버 등을 포함한 OS의 핵심부_
  - _리눅스 배포판 = Linux 커널 + 사용자 공간 프로그램 + 라이브러리 + 패키지 관리자 + init 시스템 + 기본 설정과 도구들을 묶어 실제 사용 가능한 OS로 만든 번들_
  - 리눅스 배포판의 범위 - https://distrowatch.com/
- 리소스 가시성
  1. 전역 보기(global view)
     - **모던 리눅스의 맥락에서 중요한 주제임**
  2. 로컬/가상화된 보기
     - 네임스페이스를 통하는 것으로 제공
  - 리소스 종류 - 하드웨어와 그 추상화(CPU, RAM, 파일, ..), 파일시스템, HDD, SSD, 프로세스, 네트워킹 항목(디바이스, 라우팅 테이블), 자격증명 등
  - 리눅스 네임스페이스는 서로 다른 컨텍스트를 가지며, 이들 간 동일한 PID의 프로세스가 존재할 수 있다
  - `cgroup` 을 통해 프로세스 간 격리를 제공한다
    - 가상머신을 사용하면 완전한 격리를 제공하여, 독립적인 것처럼 보이게 한다
