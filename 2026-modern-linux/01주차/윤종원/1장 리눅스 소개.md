## (지금까지의) 리눅스 이야기
### 1990년대
- 리누스 토르발스가 1991년에 이메일을 보내면서 시작되었고, 3년이 되기도 전에 리눅스 1.0.0이 나왔음
- 이때 이미 대부분의 유닉스/GNU 소프트웨어 실행이 가능했음
- 1990년대 최초 상용 제품이라 할 수 있는 Red Hat 리눅스 등장

### 2000년부터 2010년까지
- 이미 기능과 하드웨어 지원 측면에서 성숙했고, 유닉스의 한계를 넘어 성장하고 있었다.
- 구글, 아마존, IBM 등이 도입을 추진하며 엄청난 성장세를 보임
- 이로 인해 배포판 전쟁을 겪기도 했음

### 2010년 이후 오늘날까지
- 데이터 센터, 클라우드는 물론 모든 유형의 IoT 디바이스와 핸드폰에서 도입되기 시작함
- 배포 전쟁도 끝났다. 대부분 레드햇이나 데비안 기반
- 컨테이너 급부상이 이런 발전을 촉발시키기도 함

## 운영체제는 왜 필요한가
- OS가 필수는 아니다. 그러나 OS가 있으면 다양한 하드웨어 구성 요소를 추상화하고, 커널 등의 깔끔한 API를 누릴 수 있다.
- 일반적으로 OS가 공개하는 API를 시스템 콜이라고 한다.
- 고급 프로그래밍 언어는 이런 시스템 콜 위에 빌드되고, 이를 감싼 라이브러리가 제공된다.

## 리눅스 배포판
- 리눅스 배포판이란 커널과 관련 구성 요소 전체 번들
	- 패키지 관리, 파일 시스템 레이아웃, init 시스템, 셸 등등
- 물론 이걸 모두 직접 수행하는 것도 가능
	- 커널 다운로드해서 컴파일하고, 패키지 관리자 등을 선택

## 리소스 가시성
- 유닉스의 전통을 따라서 전역 보기(global view) 기능을 지원한다.
- 전역 보기란 무엇일까? 리소스란 뭘까?


- 유닉스와 확장 리눅스에는 "everything is file"이라는 말이 있다
- 이 책에서 리소스란 소프트웨어 실행을 지원하는 데 사용할 수 있는 모든 것
- 하드웨어, 추상화, 파일 시스템, HDD, SSD, 디바이스, 라우팅 테이블, credential 등


- cpu 하드웨어 정보나, 실제 파일이나, 프로세스나 등을 조회할 수 있는 명령어가 있는데
- 모든 사용자가 동일한 수의 CPU를 볼까? 같은 파일 목록을 볼까? 같은 PID는 존재할 수 있을까?
- 리눅스에는 namespace가 존재하고, 이 안에는 서로 다른 컨텍스트를 지닌 PID를 가진 여러 프로세스가 있을 수 있다.

- 즉, 리소스에는 전역 보기와 로컬 혹은 가상화된 보기가 있다
- 그렇다면 리눅스의 모든 것은 기본적으로 전역일까?
- -> 아니다.


- 리눅스에서 리소스에 대한 로컬 보기를 제공하는 방법은 네임스페이스를 통하는 것
- 또한 격리(isolation)가 존재하는데 이 단어에 '정도'는 정해져 있지 않다.
- 한 프로세스의 메모리를 제한시켜 다른 앱들도 메모리를 쓸 수 있도록 하는 걸 격리라고 보기도 하고
- VM 등을 사용하는 완전한 격리도 존재한다.
## 리눅스 운영체제의 전체 개요
![](files/Pasted%20image%2020260809202945.png)

- 모든 리눅스 배포판의 핵심에는 커널이 있고, API를 제공한다.
- 파일, 네트워크, 관측가능성은 어디에나 있으며 이들은 커널 위의 가장 기본적인 빌딩 블록으로 간주할 수 있다.


- POSIX(Portable Operating System Interface)
	- 유닉스 OS 서비스 인터페이스를 정의하는 IEEE 표준
	- 여러 운영체제 구현체 사이에서 이식성을 제공하기 위해서 생긴 것
- 리눅스는 BSD 스타일의 시스템과는 반대로 유닉스 SVID(System V Interface Definition)와 호환되며 POSIX와도 호환된다.
