# 3장 셸과 스크립팅

## 기본 개요

### 터미널
- 터미널, 터미널 에뮬레이터, 소프트 터미널 모두 터미널을 가리킨다
- 터미널은 TUI 제공하는 프로그램
- 기본적인 문자 입출력 외에도 커서, 화면 처리, 색상 지원을 위한 이스케이프 시퀀스를 지원한다.


- `TERM` 환경변수는 현재 사용 중인 터미널 에뮬레이터 값을 가지고 있다.
- `infocmp` 사용해서 이를 구성하는 것도 가능하다.

### 셸
- 셸은 명령 인터프리터 역할을 하며 터미널 내부에서 실행된다
- 스트림 통해 입출력 및 변수 지원하고
- 사용 가능한 내장 명령이 있다.
- 대화식 사용, 스크립트 사용 모두 지원


- 공식적으로 셸은 `sh`로 정의되며
- 요즘은 `bash`가 `sh` 자리를 대체해서 사용되고 있다.

#### 스트림
- 셸은 입출력을 위한 세 가지 기본 FD를 제공한다
	- `stdin` (FD 0)
	- `stdout` (FD 1)
	- `stderr` (FD 2)
- 특별하게 지정하지 않으면 셸에 입력하는 명령은 키보드에서 가져오고 출력은 화면에 전달한다.

![](files/Pasted%20image%2020260816153930.png)

- 물론 스트림을 재지정하는 것도 가능하다.
- `$FD>`와 `<$FD`를 사용해 프로세스의 출력 스트림을 재지정할 수 있다.
- `2>`는 `stderr` 스트림을 재지정하는 것
- `1>`, `>`는 `stdout`이 기본값
- `stdout`, `stderr` 모두 재지정하려면 `&>` 사용하고
- 스트림 제거하려면 `/dev/null` 사용

![](files/Pasted%20image%2020260816154040.png)

- 셸은 다음 특수 문자를 이해
	- `&`
		- 명령 마지막에 배치해 백그라운드 실행
	- `\`
		- 줄 연속(긴 명령을 다음 줄에 이어서 작성)
	- `|`
		- 한 프로세스의 `stdout` 값을 다른 프로세스의 `stdin`에 전달

![](files/Pasted%20image%2020260816154200.png)

#### 변수
- 변수를 사용해 값을 저장하고 변경할 수 있다
	- 리눅스가 노출하는 구성 항목을 처리하려는 경우나
	- 스크립트에서 사용자에게 값을 대화 형식으로 질문하려는 경우나
	- 긴 값을 한 번 정의해 입력을 줄이려는 경우


- 변수는 두 가지 종류
	- 환경변수
		- 셸 전체 설정. `env`로 조회 가능
	- 셸 변수
		- 현재 실행 상황에서 유효
		- `set` 명령으로 목록 나열 가능
		- 하위 프로세스는 셸 변수 상속하지 않음
- `export`로 환경변수 만들 수 있다
- 값 접근하고 싶다면 `$` 앞에 붙이고, `unset`으로 변수 제거 가능

#### 종료 상태
- 셸은 exit status로 명령 실행 완료를 명령 호출자에게 알린다
- 일반적으로 리눅스 명령은 종료될 때 상태를 반환한다.
- 0은 성공적으로 실행되었음을 의미하고 1 ~ 255 값은 실패를 의미한다
- 종료 상태를 확인하려면 `echo $?`를 사용한다.
- 일부 셸에서는 마지막 상태값만 확인할 수 있으므로 파이프 사용 시 주의해야 한다
- `$PIPESTATUS` 사용하면 이런 제약사항을 해결할 수 있다.

#### 내장 명령어
- `yes`, `echo`, `cat`, `read` 등이 있다
- `help`로 내장 명령어 목록을 나열할 수 있다.

#### 작업 제어
- 작업 제어는 대부분의 셸이 지원한다.
- 일반적으로 명령은 포어그라운드에서 실행된다
- 이걸 원하지 않는다면 `&`를 마지막에 넣어 백그라운드에서 실행하면 된다
- 혹은 실행 중인 프로세스에 대해 `ctrl + z` 눌러서 백그라운드로 보낼 수 있다.

![](files/Pasted%20image%2020260816161729.png)

- 셸 종료 후에도 백그라운드 프로세스를 계속 실행하려면 `nohup` 명령을 앞에 추가하면 된다
- `nohup` 없이 실행한 프로세스도 `disown` 사용하면 비슷한 효과를 얻을 수 있다.
- 사실 이보다는 터미널 멀티플렉서 사용을 추천한다.

## 터미널 멀티플렉서
- 우리는 보통 그룹으로 묶을 수 있는 다양한 작업을 수행한다.
- 이는 몇 분에서 며칠 혹은 몇 주까지 다양하다
- 이를 세션이라 부르며, 아래 요구사항이 필요
	- 창이 여러 개 필요
	- 터미널 닫아도 여전히 실행되어야 함
	- 모든 세션을 전체적으로 볼 수 있고, 세션 사이 탐색도 가능해야 함
### screen
- 원조 터미널 멀티플렉서
- 오늘날 `screen`은 유지 관리가 활발하지 않고 유연하지 않음
### tmux
![](files/Pasted%20image%2020260816163055.png)
- 세션
	- 각 작업을 위한 작업 환경 논리 단위
- 윈도(window)
	- 세션에 속한 단위. 브라우저 탭
	- 보통은 세션당 하나의 윈도
- 영역(pane)
	- 실행 가능한 단일 셸 인스턴스

- `tmux new -s test`
	- 이를 쓰면 tmux가 서버로 실행되고, 셸이 클라로 실행된다
- `Ctrl + b`로 여러 기능을 트리거할 수 있다.
- `Ctrl + b + d`로 세션 분리 후 새 세션을 열거나, `tmux attach -t test`로 기존 세션에 연결하는 것도 가능하다.

| 윈도  | 닫기       | 트리거 + `&`      |
| 영역  | 수평 분할    | 트리거 + `"`      |

## 스크립팅
- bash 스크립트는 어디서든 실행이 가능해 범용성이 높지만
- 너무 긴 스크립트의 경우 고급 언어를 쓰는 게 더 나을 수도 있다.

### 스크립팅의 기본 개요
#### 고급 데이터 유형
- 일반적으로 모든 것은 문자열로 취급
- 배열 등의 일부 고급 데이터 유형도 지원
![](files/Pasted%20image%2020260816172310.png)
#### 흐름 제어
- `if`, `for`, `while` 등도 지원
#### 함수
- 함수도 사용 가능

#### 고급 I/O
- `read` 사용하면 런타임 입력 유도 가능
![](files/Pasted%20image%2020260816172539.png)

### 이식 가능한 배시 스크립트 작성
- 스크립트 실행 환경에 대해 암시적, 명시적 가정을 하지 않는다는 것
- 셸의 유형에 따라서도 또 달라질 수 있음

#### 이식 가능한 스크립트 실행
- 스크립트는 결국 텍스트 파일이라 확장자는 중요하지 않음
- 그러나 `.sh`가 관례로 사용되는 경우가 많음


- 텍스트 파일을 스크립트로 쓰려면
	- `#!` 등의 shebang 사용해서 인터프리터 선언
	- `chmod +x`로 스크립트 실행 가능한 권한 주기
		- `chmod 750`이 더 최소한의 실행 권한이긴 함
